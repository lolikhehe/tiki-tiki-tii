# Technical decisions (deviations from the TZ)

This file records places where the implementation intentionally differs from
the technical task. Where a TZ requirement conflicts with current library
documentation, the documentation wins and the difference is noted here.

## 1. Runtime `sqlx::query_as` instead of compile-time `query!` + `.sqlx/`

**TZ (§4, §5.1, Stage 5):** use `sqlx::query!`, `.sqlx/` offline metadata and
`SQLX_OFFLINE=true` so SQL is checked at compile time.

**Decision:** the current code uses the runtime `sqlx::query_as` API with
explicit `FromRow` tuples. Rationale: the workspace must build in CI without a
live Postgres instance and without an extra `sqlx-cli` prepare step; the SQL is
small, centralized in `crates/storage/src/db.rs`, and covered by query tests.
This is a deliberate trade-off: we lose compile-time SQL verification but gain
a dependency-free build. Revisiting with `cargo sqlx prepare` is tracked as a
follow-up.

## 2. fs path passed to ffmpeg/ffprobe without `--`

The TZ mandates `--` before the URL for `yt-dlp` (implemented in
`crates/downloader/src/ytdlp.rs`). ffmpeg/ffprobe do not uniformly accept `--`
as an end-of-options marker, so their file paths are passed directly. Paths are
always generated by us (a UUID temp directory + fixed file names), never from
user metadata, so there is no option-injection surface.

## 3. Local Bot API server

The TZ requires `telegram-bot-api --local`. The bot supports it via
`TELEGRAM_API_URL`; when unset, the cloud API is used and `max_file_bytes()` is
capped at 49 MB. For files above 50 MB the local server is mandatory (Stage 6).
